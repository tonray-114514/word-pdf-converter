# Word ⇄ PDF 互转工具

一个 Windows 小工具，用于 **Word 与 PDF 双向互转**。提供两种用法：

- **桌面版**：图形界面，支持批量、拖拽，双击即用。
- **手机网页版**：手机连同一 Wi-Fi，浏览器打开即可上传转换、下载结果（转换仍在电脑本机完成，输出质量与桌面版一致）。

---

## 快速开始（桌面版）

1. 双击 **`启动程序.bat`**
2. 把 Word / PDF 文件拖进窗口（或点「添加文件」）
3. 选好输出位置，点「开始转换」

程序自带独立运行环境（`env` 目录），**不需要**你手动装 Python 库，也不会影响系统里其他 Python 环境。

如果提示缺少运行环境，说明 `env` 目录缺失或损坏，双击 **`安装依赖.bat`** 重新初始化即可（需要本机已安装 Python 3.9+）。

## 手机网页版

1. 在电脑上双击 **`启动手机网页版.bat`**
2. 窗口里会显示手机要访问的网址和访问口令，例如：

   ```
   手机访问 : http://192.168.1.5:8765/
   访问口令 : 417302
   ```

3. 手机连**同一个 Wi-Fi**，浏览器打开上面那个网址
4. 输入口令 → 选择文件 → 点「开始转换」→ 自动下载结果

**可以装到手机桌面**：在手机浏览器里选「添加到主屏幕」，之后像 App 一样点图标打开。

### 说明与限制

- **转换在电脑上完成**，所以电脑要开着、服务窗口不能关。手机只是遥控器和上传下载通道。
- **必须在同一 Wi-Fi 下**（同一局域网）。出了家门就用不了，除非另外配置内网穿透。
- **访问口令**默认随机生成并显示在电脑窗口里，防止同网络下别人误用。想关掉可以加 `--no-auth`。
- 结果文件保留 **2 小时**后自动清理；单个文件上限 **200 MB**。
- 手机上选择文件时，可以直接调用相机拍照（PDF→Word 时适合拍纸质文档，但**扫描件没有文字层，会转成图片**，需要 OCR 才能得到可编辑文字）。

### 换端口 / 关口令 / 换引擎

```bat
启动手机网页版.bat --port 8899          :: 换端口
启动手机网页版.bat --no-auth            :: 关闭口令（同网络任何人都能用）
启动手机网页版.bat --password 123456    :: 指定固定口令
启动手机网页版.bat --engine office      :: 强制用 Word/WPS 转换
启动手机网页版.bat --engine libreoffice :: 强制用 LibreOffice 转换
```

`--engine` 的三种取值：

| 取值 | 含义 |
|---|---|
| `auto`（默认） | 有 Word/WPS 就用它，否则用 LibreOffice |
| `office` | 强制用 Word 或 WPS（质量最好） |
| `libreoffice` | 强制用 LibreOffice —— **用于把本服务部署到没有 Word 的服务器上** |

如果指定的引擎不可用，启动时会直接给出警告，手机端也会自动禁用对应方向，不会让你白等。

### 手机端界面说明

- **最近转换记录**：页面底部可以展开最近 20 次转换，2 小时内可重复下载。
  手机上误关了页面、或自动下载没触发时，用这个找回结果。
- **引擎提示**：若这台电脑没有 Word 引擎，页面会明确提示并自动禁用「Word → PDF」，
  只保留可用的「PDF → Word」。
- **可安装到主屏幕**：支持 PWA，加到主屏幕后有独立图标、全屏打开。

### 手机版能用哪些功能

| 功能 | 手机网页版 | 桌面版 |
|---|---|---|
| Word → PDF | ✅ | ✅ |
| PDF → Word | ✅ | ✅ |
| 最近记录 / 重复下载 | ✅ | ➖ |
| 一次一个文件 | ✅ | ✅ |
| 批量多文件 | ➖（一个一个来） | ✅ |
| 拖拽 | ➖ | ✅ |
| 输出目录自选 | ➖（浏览器下载目录） | ✅ |

### 想让手机脱离这台电脑（部署到服务器）

手机版服务端本身不依赖 Windows —— 只有「Word → PDF」用 COM 时才需要。
所以把它放到一台 Linux 服务器上、装上 LibreOffice，手机就能在外网独立使用：

```bash
# 服务器上（Linux）
apt install libreoffice-writer          # 提供 Word→PDF 引擎
pip install python-docx PyMuPDF         # 转换核心依赖
python3 server.py --engine libreoffice --port 8765
```

然后把端口对外开放（或用 Nginx 反代 + HTTPS）。
注意：`--engine libreoffice` 输出的 PDF 排版与 Word 略有差异，
追求完全一致仍需在装有 Word 的 Windows 上转换。

> PDF → Word 这一方向纯 Python 实现（PyMuPDF + python-docx），
> 在 Windows / Linux / macOS 上都能跑，不受上面限制。

## 转换能力

### Word → PDF

调用本机 **Microsoft Word** 排版后导出，效果与你在 Word 里手动「另存为 PDF」**完全一致**：
文字可选中、可搜索，标题会自动生成 PDF 目录书签。

支持格式：`.docx` `.doc` `.docm` `.dotx` `.dot` `.rtf` `.odt` `.txt`

> 未安装 Word 时，程序会自动改用 **LibreOffice**（若已安装）作为备用引擎。

### PDF → Word

用 PyMuPDF 解析 PDF 版面，再生成**真正可编辑**的 `.docx`：

| 能力 | 说明 |
|------|------|
| 段落还原 | 按字号、行距、缩进判断换行与分段，合并被 PDF 拆散的行 |
| 标题识别 | 依据字号层级与「第一章 / 1.1 / 摘要 / 参考文献」等编号样式推断标题级别 |
| 列表识别 | 识别 `•` `·` `-` `*` 等项目符号，还原为 Word 列表样式 |
| 表格还原 | 识别表格结构，还原为真正的 Word 表格（可继续编辑） |
| 图片提取 | 提取页面内嵌图片并居中插入 |
| 扫描件兜底 | PDF 没有文字层时，整页渲染为图片插入，**保证内容不丢失** |
| 分栏处理 | 检测页面分栏并按栏读取，避免左右栏文字交错 |

## 使用要点

**批量转换**：一次拖入多个文件，转换方向可设为「自动识别」（按扩展名判断），也可强制单向。

**输出位置**：默认输出到「桌面」，可改成任意目录；勾选「与源文件同目录」则就地输出。
同名文件**不会**被覆盖，会自动生成 `(1)` `(2)` 后缀。

**PDF → Word 选项**：可在右侧面板关闭标题识别、图片提取、表格还原、分页等，按需取舍。

**速度**：Word 首次启动约需 10 秒，之后同一批次内会复用 Word 进程，速度明显加快。
扫描件转图片会明显变慢（图片分辨率可在代码中调整）。

## 命令行用法

图形界面不是唯一入口。需要在脚本里批量处理时，可以用命令行：

```bat
:: 显示引擎信息
env\Scripts\python.exe cli.py --list-engine dummy

:: Word 转 PDF
env\Scripts\python.exe cli.py --to-pdf 报告.docx 合同.doc -o D:\输出

:: PDF 转 Word（不提取图片）
env\Scripts\python.exe cli.py --to-word 手册.pdf -o D:\输出 --no-images

:: 自动识别方向，处理整个文件夹
env\Scripts\python.exe cli.py D:\文档 -o D:\输出
```

常用参数：`--to-pdf` `--to-word` `-o/--outdir` `--same-dir`
`--no-images` `--no-tables` `--no-headings` `--no-pagebreak`

## 常见问题

**提示「本机未检测到 Microsoft Word，也没有 LibreOffice」，但电脑上明明装了 Word**
最常见的原因是**用错了 Python 解释器**：程序依赖装在自带的 `env` 目录里，
如果你用系统的 Python 直接运行（例如在终端敲 `python cli.py --diagnose dummy`），
就找不到 pywin32，于是误报没有 Word。

正确做法：
- 双击 **`启动程序.bat`** 运行（它固定使用自带环境）；
- 若要在终端里跑，显式指定自带解释器：
  `env\Scripts\python.exe cli.py --diagnose dummy`

`app.py` 和 `cli.py` 已内置自动切换：即使被系统 Python 启动，也会自动换成自带
`env` 重新运行。用 `诊断报告.bat` 可以看到当前实际使用的是哪个 Python。

**提示「Word 未能引发事件」或转换失败**
先手动打开一次 Word 再关闭，确认没有登录、激活、更新之类的弹窗；然后重试。
Word 正在显示对话框时无法被自动化调用。

**PDF 转出来的 Word 排版和原文不一样**
PDF 格式本身不保存「段落」「标题」这类结构信息，任何转换工具都无法 100% 还原原排版。
本工具的目标是**内容完整、结构可编辑**。复杂分栏、公式、艺术字可能出现顺序或样式偏差；
如需像素级保真，建议用「Word → PDF」方向的原始文件，而不是从 PDF 反推。

**扫描件转出来的是图片，不能编辑文字**
扫描件本身没有文字层（就是一张图片），没有 OCR 就不可能得到文字。
程序会整页转成图片以保证内容不丢。若需要可编辑文字，需先用 OCR 工具处理。

**支持转换受密码保护的 PDF 吗**
不支持，请先解除密码后再转换。

**文件被占用 / 转换失败**
请先关闭正在用 Word 或 PDF 阅读器打开的同名文件。

## 排查问题

任何「转换不了 / 未检测到 Word」之类的问题，按顺序试：

1. **双击 `环境体检.bat`** —— 12 项自检，看哪一项失败
2. **双击 `诊断报告.bat`** —— 列出用的是哪个 Python、pywin32 是否可用、
   Word/WPS/LibreOffice 的搜索过程、COM 组件注册状态，并给出结论
3. 手机版问题还可以看服务窗口里的启动横幅（引擎、地址、警告）

桌面版界面顶部也有「诊断报告」按钮，可一键复制报告。

### 双击 .bat 没反应，或窗口一闪而过

先确认批处理文件的**编码与换行符**是否被改坏。Windows 的 cmd.exe 对此有两个硬性要求：

| 要求 | 违反后的现象 |
|---|---|
| 换行必须是 **CRLF** | cmd 把命令拆碎，报 `'xxx' is not recognized`，脚本不执行 |
| 中文内容必须用 **GBK**（中文系统 ANSI 代码页）编码 | 中文变乱码并吞掉引号，`set "VAR=..."` 被破坏，启动失败 |

用代码编辑器或 Git 改动本目录的 `.bat` 时，很容易被自动转成 UTF-8 + LF，从而踩到这个坑。
**`环境体检.bat` 自带这项检查**，也可以单独运行：

```bat
env\Scripts\python.exe tools\check_bat.py
```

若检查失败，把文件另存为「ANSI 编码 + CRLF 换行」即可恢复
（用 `安装依赖.bat` 重建环境不会影响批处理文件本身）。

### 已知环境问题

如果你机器上装了**多套 Python**（例如 python.org 的 Python 与 uv 安装的 Python 并存），
可能出现别的程序报 `libssl-3-x64.dll` 找不到 —— 那是两套 Python 的 OpenSSL 命名不同所致，
**与本工具有关的转换功能无关**：本工具自带独立运行环境，不受影响。

## 技术实现

| 环节 | 方案 |
|------|------|
| Word → PDF | Word/WPS COM 自动化（`ExportAsFixedFormat`），保留标题书签与文档结构标签 |
| Word → PDF（备用） | LibreOffice 命令行（`soffice --convert-to pdf`），无 Word 时自动回退 |
| PDF 解析 | PyMuPDF，使用字级坐标还原段落、缩进与分栏 |
| 生成 docx | python-docx，设置中文字体、A4 版心、标题样式与 Word 表格 |
| 桌面界面 | tkinter + tkinterdnd2（拖拽） |
| 手机界面 | 纯标准库 `http.server` + 单页响应式网页（PWA 可安装） |
| 线程模型 | 桌面版后台线程 + 队列回传进度；手机版单工作线程串行（Office COM 对多线程敏感） |
| 文件传输 | 手机端以原始二进制流上传，避免 multipart 解析开销与兼容问题 |
| 下载鉴权 | 结果文件带随机令牌 + 中文文件名按 RFC 5987 编码 |

图片处理全程使用内存流，不落盘，避免临时目录权限问题。
